# Chezmoi Dotfiles Changes - November 16, 2026

## Summary

Captured two weeks of deployed-only changes into the source, encrypted the Claude
auto-mode entries that describe the homelab (this repo is public), fixed the `gh`
credential-helper lookup in the gitconfig template, and rewrote the
`integrate-changes` skill.

## Changes

### 1. Captured Deployed Drift

Since 2026-11-02 the deployed files had been edited directly and the source had fallen
behind, so `chezmoi apply` would have removed real configuration.

- `dot_claude/private_settings.json.tmpl`: credential `Read`/`Edit` deny rules, the
  sandbox block (enabled, `denyRead`/`denyWrite`, credential env-var denies, GitHub
  network domains), ask rules for prod `ansible-playbook`, auto-mode `allow` and
  `environment` entries, the `claude-flow` and `eric-board` plugins and marketplaces,
  the `flow-*`/`cf-*` allows, and `tui: fullscreen`.
- Removed the `ea-private` plugin and marketplace, which were no longer in the deployed
  file. This reverses the 2026-11-02 change.
- `dot_claude/skills/boss/SKILL.md`, `boss/standards.md`: GitHub-identity rule and the
  herdr `--name` flag.
- `dot_claude/skills/claude-log/SKILL.md`: log path is `~/Vaults/Claude/ClaudeLog/`.
- `dot_zshrc.tmpl`: the oMLX `~/.omlx/bin` PATH block, and a `cf-dispatch` alias.

### 2. Encrypted Private Auto-Mode Entries

- `.private/claude.json.age`: four `autoMode.environment` entries and one
  `autoMode.allow` entry, age-encrypted with a post-quantum key.
- `.private/age-recipients.txt`: the public half of that key.
- `.chezmoi.toml.tmpl`: sets `encryption = "age"` with the identity at
  `~/.config/chezmoi/key.txt`. Run `chezmoi init` once on each machine to pick it up.
- `dot_claude/private_settings.json.tmpl`: decrypts and splices the entries in only
  when the identity file exists; otherwise renders without them.
- `SETUP.md`: how to fetch the key from 1Password on a new machine.

### 3. gitconfig: `gh` Lookup No Longer Depends on PATH

`dot_gitconfig.tmpl` used `lookPath "gh"`. Inside a Claude Code session the claude-flow
plugin puts a `gh` wrapper first on PATH, so chezmoi rendered the wrapper as the GitHub
credential helper there. The wrapper refuses to run without a role token, so applying
from a Claude session would have broken HTTPS git in a normal terminal.

The template now checks `/opt/homebrew/bin`, `/usr/local/bin`,
`/home/linuxbrew/.linuxbrew/bin` and `/usr/bin` first, and its PATH fallback rejects
any path containing `claude-agents`.

### 4. Rewrote the `integrate-changes` Skill

`.claude/skills/integrate-changes/SKILL.md` now decides a direction per pending file
(apply the source, or fold the deployed change back into it) using the `chezmoi status`
columns and the source file's git history, flags changes to permissions, sandbox, hooks
and credential config, and does the source-side work. It never runs `chezmoi apply`.

The other four chezmoi skills were rewritten the same day:

- `chezmoi-status`: reads the `chezmoi status` columns to say which side changed, instead
  of treating every removed line as high risk; reports the branch, the age identity and
  externals; is explicitly read-only.
- `chezmoi-backup`: the work is now done by `backup.sh` in the skill directory. It also
  records files that apply would create and keeps the saved diff owner-only.
- `chezmoi-undo`: the work is now done by `undo.sh`. It shows what differs before
  restoring, saves the current copies first (`<timestamp>_pre-undo`), and asks before
  overwriting.
- `chezmoi-unmanaged`: works in groups instead of one file at a time, reads a file before
  adding it to this public repo, and no longer tells the reader to use absolute paths in
  the ignore file (a leading slash breaks every chezmoi command).

`CLAUDE.md` and the skill both record that this repo is public and that host names,
internal domains, tailnet names and IPs must not be committed as plain text. The names
of private GitHub repos are fine to publish.

### 5. gh CLI Extensions

`.chezmoiscripts/run_onchange_after_install-gh-extensions.sh.tmpl` installs the gh
extensions in its list (currently `github/gh-stack`) when they are missing. It re-runs
when the list changes or when `gh` first appears on the machine, skips quietly when `gh`
is not installed, and does not need `gh auth login` for public extensions.

## Verification

- With the key, `chezmoi diff --exclude=externals` is empty: the settings template
  renders byte-identical to the deployed file.
- Without the key, and with no encryption configured, the template renders valid JSON
  without the private entries.
- Tested on one Mac with chezmoi's built-in age. Not tested on Linux or a second machine.

## Known Issues

- `chezmoi age-keygen -y` fails on a post-quantum identity ("unexpected identity
  type"). The public key is also the `# public key:` comment in the identity file.
