# Chezmoi Dotfiles Changes - November 24, 2026

## Summary

The Forgejo domain in the Claude Code sandbox's network allowlist is now
encrypted like the other homelab entries, so the public settings template no
longer names an internal domain. The private auto-mode entries name both Macs
instead of calling one of them "this Mac", and the unused `wshobson/agents`
marketplace is gone. Eric's three plugin repos and their marketplaces are
renamed so each name says which product it serves and whether it is private.
The default branch is now `main`. Drift in the deployed settings and the boss
skill is captured back into the source.

## Changes

### 1. Sandbox Homelab Domains Moved Into the Encrypted File

- `.private/claude.json.age`: new `sandboxAllowedDomains` list holding the Forgejo
  domain, which `dot_claude/private_settings.json.tmpl` listed in plain text in
  `sandbox.network.allowedDomains` since 77081f5.
- `dot_claude/private_settings.json.tmpl`: splices that list in at the top of
  `allowedDomains` when the age identity exists, and defaults it to empty
  otherwise. A machine without the key gets only the GitHub domains, so sandboxed
  commands there cannot reach the Forgejo.

The domain is still in git history. It is not rewritten: the repo has been
public with it, and the name alone grants nothing.

### 2. Private Auto-Mode Entry Names Both Macs

- `.private/claude.json.age`: the internal-services environment entry called the
  first Mac "this Mac", which was wrong for sessions on the second Mac. It now
  lists both Macs by name.

### 3. Dropped the `wshobson/agents` Marketplace

- `dot_claude/private_settings.json.tmpl`: removed it from
  `extraKnownMarketplaces`. No plugin from it was enabled or installed. It was
  declared as `agents`, but its `marketplace.json` names it
  `claude-code-workflows`, so the entry never matched the registered marketplace.
  Remove the registration on each machine with
  `claude plugin marketplace remove claude-code-workflows`.

### 4. Renamed the Plugin Repos and Marketplaces

Each repo's name now says which product its plugins run in and whether it is
private, and its marketplace name is the short form of the same thing:

| Repo (was) | Repo (now) | Marketplace (was → now) |
|---|---|---|
| `claude-plugins` | `claude-code-plugins` | `ea-claude` → `ea-cc` |
| `claude-ea-codes` | `claude-code-plugins-priv` | `ea-codes` → `ea-cc-priv` |
| `private-claude-plugins` | `claude-desktop-plugins-priv` | `ea-private` → `ea-desktop-priv` |

- `dot_claude/private_settings.json.tmpl`: the `ea-cc` and `ea-cc-priv` marketplace
  keys, their GitHub repos and local-clone paths, and the five plugin IDs in
  `enabledPlugins` (`cleanroom`, `dagu`, `git` `@ea-cc`; `ea-codes`, `tmux`
  `@ea-cc-priv`). `ea-desktop-priv` is not in the template: claude.ai syncs its `ea`
  plugin as `ea@synced`.
- `.chezmoiremove`: comment names `cleanroom@ea-cc`.
- Plugin names are unchanged, so skills keep their names (`ea-codes:claude-log`,
  `ea:capture`).

The repo renames and the `name` field in each `marketplace.json` happen on
GitHub, and must land before this template is applied, or Claude Code reports
that the marketplace name does not match. Then on each machine, remove the old
registrations and install from the new ones (`claude plugin marketplace remove
ea-claude`, `... ea-codes`, then `claude plugin install <plugin>@ea-cc` and
`@ea-cc-priv`), and rename any local clone under `~/src/github.com/ericanderson/`.

### 5. Default Branch Renamed From `master` to `main`

- Renamed on GitHub, which redirects the old name. There were no open PRs, branch
  protection or rulesets to move.
- `CLAUDE.md` (Development Workflow step 4) and `.claude/skills/chezmoi-status/SKILL.md`
  now say `main`.
- The `master` entries in the settings template's push ask rules and auto-mode
  rules stay: they cover every repo, not just this one.

Update each existing clone, including chezmoi's source directory on every
machine:

```bash
git -C ~/.local/share/chezmoi fetch --prune origin
git -C ~/.local/share/chezmoi branch -m master main
git -C ~/.local/share/chezmoi branch -u origin/main main
git -C ~/.local/share/chezmoi remote set-head origin --auto
```

### 6. Captured Deployed Settings Drift

`dot_claude/private_settings.json.tmpl` now matches what had been added to
`~/.claude/settings.json` outside chezmoi:

- From claude-flow's settings installer (`scripts/lib/settings.jq`): the
  `Bash(gh issue edit *)` allow and its 13 ask rules (body, `--attach`, assignee
  and `stuck` label edits still prompt), the deny on
  `~/Library/LaunchAgents/com.ericanderson.claude-flow-dispatch.plist`, and three
  `autoMode.environment` lines on GitHub identity, rulesets and the tech-lead
  merge gate. The `flow-*` allows are removed; claude-flow deleted those
  commands on 2026-11-23.
- Sandbox: network access to `index.crates.io` and `static.crates.io`, and writes
  to `~/.cargo/registry/cache` and `~/.cargo/registry/index`, so sandboxed cargo
  builds can fetch crates.
- `remember@claude-plugins-official` removed from `enabledPlugins`; it had been
  uninstalled.

### 7. Boss Skill Uses herdr-core

- `dot_claude/skills/boss/SKILL.md`, `standards.md`: re-added from the deployed
  copies, rewritten on 2026-11-23 for `hc` and `herdr-app`. Each worker gets its
  own Herdr space via `herdr-app do space.new`; git creates and removes the
  worktree under `~/.herdr/worktrees/`.

## Verification

- With the key, `chezmoi diff ~/.claude/settings.json` shows only the removed
  marketplace and the reworded environment entry. `allowedDomains` renders
  unchanged.
- With the identity check forced off, the template renders valid JSON with the
  five GitHub domains, two `autoMode.allow` and two `autoMode.environment`
  entries, and no internal names.
- No plain-text internal domain, tailnet name or IP remains in the source tree
  (`grep -rli` outside `.git`).
- After the rename, the template renders valid JSON on this Mac (GitHub sources)
  and with every local clone and `claude-flow` forced present (directory
  sources at the new clone paths).
