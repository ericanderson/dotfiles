# Chezmoi Dotfiles Changes - September 14, 2026

## Summary

Changed the SSH auto-attach block in `dot_zshrc.tmpl` to target tmux session `0`
instead of `default`, and collapsed the attach-or-create pair into a single
`tmux new-session -A`.

## Changes

### 1. SSH Auto-Attach Now Targets Session `0`

`dot_zshrc.tmpl` hardcoded the session name `default`, so every SSH login landed in
a session named `default` rather than the numerically-named session tmux creates on
its own:

```sh
# before
tmux attach-session -t default || tmux new-session -s default

# after
tmux new-session -A -s 0
```

Two things changed:

- **Target renamed to `0`.** This is the name bare `tmux` / `tmux new-session` assigns
  when no `-s` is given, so a session started by hand before the auto-attach block runs
  is now joined instead of being shadowed by a second, separate session.
- **`-A` replaces the `||` fallback.** `new-session -A` attaches if the target exists and
  creates it otherwise, which is exactly what the two-command form did — but without
  emitting `no server running on /tmp/tmux-*/default` to stderr on the first login after
  a reboot. `-A` has been available since tmux 1.8, well below anything deployed here.

The surrounding guard conditions (`$PS1`, `$TERM` not screen/tmux, `$TMUX` unset,
`$SSH_CONNECTION` set, `$VSCODE_IPC_HOOK_CLI` unset) were left untouched.

### Impact

- Applied on this machine; `chezmoi diff --exclude externals` is clean for `.zshrc`
- Takes effect on a given host only after `chezmoi update` runs **there** — this block
  fires on the machine being SSH'd *into*, not the one initiating the connection
- Hosts with a live session named `default` will get a new, empty `0` alongside it.
  To carry the existing one over instead, run `tmux rename-session -t default 0` on that
  host before reconnecting.
