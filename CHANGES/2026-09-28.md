# Chezmoi Dotfiles Changes - September 28, 2026

## Summary

Removed the `Bash(git push * :*)` ask rule from `dot_claude/private_settings.json.tmpl`.
It triggered a warning on every Claude Code startup and never matched anything.

## Changes

### 1. Removed Dead `git push * :*` Ask Rule

The rule was meant to prompt before refspec deletes such as `git push origin :branch`.
Claude Code (2.1.284) treats a trailing `:*` as the legacy prefix syntax, and when the
rule also contains another `*` it matches the whole thing as a literal prefix:

```
Permission ask rule (~/.claude/settings.json): Bash(git push * :*) mixes * with the
trailing :* prefix syntax, so it is matched as a literal prefix (the * is not expanded)
and matches only commands containing a literal * at that position.
```

There is no escape for a literal colon followed by a wildcard. Every spelling tried
(`:**`, `:* *`, `*:*`) still produces a startup warning. `Bash(git push * :**)` does match
correctly (tested with an `echo` analogue), but it swaps in a different warning, so the
rule was dropped instead.

The legacy `prefix:*` rules in `.claude/settings.local.json` (e.g. `Bash(tmux set:*)`)
are still valid. They're equivalent to `prefix *` and produce no warnings.

### Impact

- No more startup warning once applied.
- No behavior change. The rule never matched, so `git push <remote> :<ref>` was already
  auto-allowed by `Bash(git push *)` and still is. `--delete` and force pushes still prompt.
