# Chezmoi Dotfiles Changes - November 19, 2026

## Summary

Read-only `gh api graphql` queries no longer ask for approval. Mutations, REST
writes and anything the hook cannot read exactly still prompt. Five unused or
disabled Claude Code plugins were uninstalled, and `context7` is enabled again.

## Changes

### 1. Added the `gh-graphql-query-allow` PermissionRequest Hook

- `dot_claude/hooks/executable_gh-graphql-query-allow.py`: new. Runs only when
  Claude Code is about to show a permission prompt for a Bash call. Answers
  "allow" when the call is a single `gh api graphql` command whose query text
  (inline, `-F query=@file` or `--input file.json`) never contains `mutation` or
  `subscription`. Otherwise prints nothing, so the prompt appears as before.
- `dot_claude/private_settings.json.tmpl`: registers it under `PermissionRequest`
  with matcher `Bash`.

The ask rules for `gh api graphql`, `-f`/`-F`/`--input` and `-X`/`--method` are
unchanged. A PreToolUse hook could not have done this: its "allow" does not
override ask rules, while a PermissionRequest hook's "allow" does (deny rules
still win). See https://code.claude.com/docs/en/hooks.md#permissionrequest-decision-control.

It fails closed. It stays silent for shell syntax beyond plain words, single
quotes and double quotes without `$`, backtick or backslash; for queries it
cannot read or that come from stdin; for a non-`query` field that reads a file
(`-F name=@path`, which would upload it); for non-identifier field names; and for
any flag outside a fixed list of `gh api` flags (so `-X`/`--method`, short-flag
clusters such as `-iF`, `--`) or a bare argument after `graphql`.

### 2. Pruned `enabledPlugins`

All from `claude-plugins-official`, in `dot_claude/private_settings.json.tmpl`:

- Dropped `code-review` and `code-simplifier`: duplicates of the built-in
  `/code-review` and `/simplify`, no recorded use since 2026-09-03.
- Dropped `commit-commands`: no recorded use; it adds attribution lines, and
  `/clean_gone` runs `git worktree remove --force` and `git branch -D`.
- Dropped `claude-code-setup`: no recorded use; a one-time recommender for new
  projects.
- Dropped `superpowers`: already disabled.
- `context7`: now enabled (was `false`). It had been off only because a former
  workplace required it.
- Kept `hookify` although no `hookify.*.local.md` rule exists anywhere under the
  home directory (searched 8 levels deep): cheap to keep in case one is written.

The plugins were uninstalled (and `context7` reinstalled) with `claude plugin` on
this Mac. On other machines the template only changes `enabledPlugins`; run the
same commands there to delete the cached copies or install `context7`.
- `rust-analyzer-lsp` and `typescript-lsp` were reinstalled on this Mac to pick up
  the 2026-11-06 upstream change (their version number did not change, so the
  installed February copies were never refreshed). No source change.

## Verification

- 50 cases piped through the hook as PermissionRequest events: plain, file and
  `--input` queries are allowed; mutations, subscriptions, chained commands,
  `$(...)`, `$'\x6d...'`, globs, `~`, zsh `=cmd`, file-reading variables,
  short-flag clusters, unknown flags and REST writes all prompt. Three of these
  are bypasses automated security reviews found in earlier versions
  (comment/string stripping order, shlex differing from the shell, `-iF`
  clusters).
- Live: after `chezmoi apply`, a read-only `gh api graphql -F query=@file` ran
  without a prompt.
- Plugins: after the uninstalls, `chezmoi diff` on `.claude/settings.json` shows
  only the order of the two reinstalled LSP keys.

## Known Issues

- The test cases are not in the repo; there is no test convention here yet.
- The hook needs `python3`. Without it the hook errors and the prompt shows, as
  before.
