# Chezmoi Dotfiles Changes - October 10, 2026

## Summary

Ported two Claude Code permission changes from the hand-edited `~/.claude/settings.json`
into `dot_claude/private_settings.json.tmpl` so the next `chezmoi apply` keeps them.
Agents in auto mode kept stopping on routine `git merge origin/main`. The blanket
`Bash(git merge *)` ask rule is replaced with an auto-mode classifier rule, plus ask rules
for pushes to `main`/`master`.

## Changes

### 1. Replaced `Bash(git merge *)` Ask Rule With Push-to-Main/Master Asks

Removed `Bash(git merge *)` from `permissions.ask` and added 12 rules in its place, six
each for `main` and `master`:

```
Bash(git push * main)            Bash(git push * main *)
Bash(git push *:main)            Bash(git push *:main *)
Bash(git push *refs/heads/main)  Bash(git push *refs/heads/main *)
```

These cover `git push origin main`, `HEAD:main`-style refspecs and fully qualified
`refs/heads/main`. None end in `:*`, so they avoid the legacy-prefix warning that
removed `git push * :*` on 2026-09-28.

### 2. Added `autoMode.soft_deny` Protected Branch Merge Rule

`autoMode.soft_deny` is now `"$defaults"` plus a "Protected Branch Merge" rule. In auto
mode the classifier blocks `git merge`/`git pull`/`git rebase` that land commits on
`main`, `master`, `develop`, `production` or `release/*`. It still allows merging
`origin/main` into a feature branch and fast-forward-only updates of a protected branch
to its own upstream. `autoMode.environment` is unchanged.

### 3. Template Key Order Now Matches What Claude Code Writes

Claude Code had rewritten `~/.claude/settings.json` in its own key order (`permissions`
before `hooks`, `type` before `command` and so on). `chezmoi diff` therefore showed ~400
lines of churn for what were really four changes. The template is now generated in the live
file's order and renders byte-identical to it. Claude Code keeps existing key order and
appends new keys at the end, so later diffs should only show real changes.

### 4. Dropped Work-Machine Branches From the Settings Template

There is no work machine anymore, so the `$isWork` hostname check and everything behind it
are gone from `dot_claude/private_settings.json.tmpl`. That covers the attribution
trailers, `"model": "opus[1m]"`, the `.workPlugins` range, the `{{ .workMarketplace }}`
marketplace, and the personal-only guards on `ea-codes`, `tmux` and the context7
permissions. The only template logic left is the herdr hook gate. The `.workPlugins`,
`.workMarketplace` and `.internalGitHost` data in `.chezmoi.toml.tmpl` is now unused here.

### 5. Captured Other Live-Only Settings

- `modelSettings."claude-opus-5-5".effortLevel: "high"`.
- herdr's `SessionStart` hook (`bash ~/.claude/hooks/herdr-agent-state.sh session`,
  timeout 10). herdr installs that script itself and chezmoi doesn't manage it, so the hook
  is gated on `stat` of the script at apply time. Machines without herdr don't get a hook
  that would fail at every session start. If herdr is installed later, the hook appears on
  the next `chezmoi apply`.
- Ghostty `keybind = cmd+k=text:\x1b[107;7u` (Cmd+K sends Ctrl+Alt+K) in
  `dot_config/ghostty/config`. It had been added to the live config only, so `chezmoi apply`
  would have removed it.

### Impact

- Feature-branch merges of `origin/main` no longer prompt in auto mode.
- Pushes naming `main`/`master` as the destination now prompt. Other pushes are still
  auto-allowed by `Bash(git push *)`. Force pushes and `--delete` still prompt.
- On this machine the live file already has these values. Other machines pick them up on
  their next `chezmoi apply`.
