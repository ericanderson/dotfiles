# Chezmoi Dotfiles Changes - October 10, 2026

## Summary

Ported two Claude Code permission changes from the hand-edited `~/.claude/settings.json`
into `dot_claude/private_settings.json.tmpl` so the next `chezmoi apply` keeps them.
Agents in auto mode kept stopping on routine `git merge origin/main`. The blanket
`Bash(git merge *)` ask rule is replaced with an auto-mode classifier rule, plus ask rules
for pushes to `main`/`master`.

## Changes

### 1. Replaced `Bash(git merge *)` Ask Rule With Push-to-Main/Master Asks

Removed `Bash(git merge *)` from `permissions.ask` and added 12 rules in its place, six
each for `main` and `master`:

```
Bash(git push * main)            Bash(git push * main *)
Bash(git push *:main)            Bash(git push *:main *)
Bash(git push *refs/heads/main)  Bash(git push *refs/heads/main *)
```

These cover `git push origin main`, `HEAD:main`-style refspecs and fully qualified
`refs/heads/main`. None end in `:*`, so they avoid the legacy-prefix warning that
removed `git push * :*` on 2026-09-28.

### 2. Added `autoMode.soft_deny` Protected Branch Merge Rule

`autoMode.soft_deny` is now `"$defaults"` plus a "Protected Branch Merge" rule. In auto
mode the classifier blocks `git merge`/`git pull`/`git rebase` that land commits on
`main`, `master`, `develop`, `production` or `release/*`. It still allows merging
`origin/main` into a feature branch and fast-forward-only updates of a protected branch
to its own upstream. `autoMode.environment` is unchanged.

### Impact

- Applies to both work and personal machines. Neither section is `$isWork`-specific.
- Feature-branch merges of `origin/main` no longer prompt in auto mode.
- Pushes naming `main`/`master` as the destination now prompt. Other pushes are still
  auto-allowed by `Bash(git push *)`. Force pushes and `--delete` still prompt.
- On this machine the live file already has these values. Other machines pick them up on
  their next `chezmoi apply`.
